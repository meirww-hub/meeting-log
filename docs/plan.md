# תוכנית: Meeting Log - הקלטה, תמלול, סיכום ו-TO DO אוטומטי

**שם המוצר: "Meeting Log"** (לא "MeetingScribe" כפי שהוצע בטיוטה הראשונית -
הוחלף ב-2026-08-07 כדי להתאים לשם פרויקט ה-GCP `meeting-log`).

## הקשר (Context)

המטרה: אפליקציית אנדרואיד שמקליטה שיחות/פגישות, מתמללת אותן לזרם טקסט שטוח
(ללא זיהוי דוברים), מפיקה סיכום איכותי הניתן לעריכה, ומחלצת ממנו רשימת
משימות (TO DO) - כאשר משימות עם תאריכים מוצגות כציר זמן מסוג גאנט עם אבני
דרך. כל התוצרים נשמרים אוטומטית בגוגל דרייב של המשתמש, בתיקייה שנוצרת לפי
תאריך + כותרת הנושא.

> **הערה (2026-08-24):** התוכנית המקורית כללה זיהוי/הפרדת דוברים (diarization,
> speaker embeddings, פרופילי קול חוצי-הקלטות, תיוג "דובר 1/2" ↔ שם אמיתי).
> הפיצ'ר הוסר לגמרי מהמוצר - ראה "הוסר: זיהוי דוברים" למטה. הסעיפים בתוכנית
> הזו שמתארים אותו נשארים כתיעוד היסטורי בלבד ואינם משקפים את המצב הנוכחי.

זהו פרויקט חדש (תיקייה ריקה, ללא חשבונות/מפתחות API קיימים). המשתמש ביקש
שפת ממשק/תמלול עברית בעיקרה. אין העדפת ארכיטקטורה - הומלץ סטאק Google-first
(Drive, Firestore) בשילוב Gemini API (Google AI Studio) גם לתמלול וגם
לסיכום/חילוץ משימות - הוחלף מ-Claude (לסיכום) ומ-Google Cloud Speech-to-Text
(לתמלול) ב-2026-08-07, כדי לנצל את השכבה החינמית של Gemini במקום שני
שירותים בתשלום/מוגבלים.

## ארכיטקטורה מומלצת

```
[אפליקציית אנדרואיד]
   → מקליטה (MediaRecorder), מעלה קובץ אודיו לשרת עיבוד (Cloud Run)
[שרת עיבוד - Cloud Run, Python]
   1. תמלול גנרי (זרם קטעי טקסט + timestamps, בלי זיהוי דוברים) באמצעות
      Gemini API (הבנת אודיו)
   2. Gemini API: סיכום איכותי + חילוץ משימות (JSON: תיאור, אחראי, תאריך)
   3. יצירת תיקייה ב-Drive "YYYY-MM-DD - <נושא>" והעלאת:
      - קובץ האודיו המקורי
      - תמלול מלא (Google Doc)
      - סיכום (Google Doc - ניתן לעריכה חופשית ב-Drive)
      - TO DO + גאנט (Google Sheet: טבלת משימות + טאב גאנט חזותי
        לפי תאריכים; ללא תאריכים → רשימת TO DO רגילה)
   4. (אופציונלי) יצירת אירועי אבן-דרך ביומן Google Calendar
```

**רכיבים טכניים מרכזיים:**
- אפליקציית אנדרואיד (Kotlin): הקלטה, ניהול העלאות ברקע (WorkManager),
  Google Sign-In (OAuth ל-Drive/Calendar), מסך היסטוריית הקלטות.
- Backend (Python, Cloud Run): pipeline העיבוד המלא (תמלול → סיכום/משימות
  → כתיבה ל-Drive).
- Firestore: מטא-דאטה של הקלטות/סטטוס עיבוד.
- Google Drive API: יצירת תיקיות/קבצים לפי הפורמט המבוקש.
- Gemini API (Google AI Studio, שכבה חינמית): תמלול עם timestamps (audio
  understanding), סיכום איכותי, וחילוץ משימות/תאריכים במבנה JSON - שלושתם
  דרך אותו מפתח API יחיד.
- (אופציונלי, שלב מאוחר) Google Calendar API: דחיפת אבני דרך כאירועים.

**דרישות הקמה מקדימות אצל המשתמש** (לפני תחילת פיתוח בפועל):
- פרויקט Google Cloud חדש + הפעלת Drive API, Firestore
  (Calendar API אופציונלי).
- מפתח Gemini API (Google AI Studio) לתמלול וגם לסיכום/חילוץ משימות.
- OAuth consent screen + client ID לאפליקציית האנדרואיד.

## הוסר: זיהוי דוברים (2026-08-24)

התוכנית המקורית (למטה, "שלב 2") כללה זיהוי/הפרדת דוברים: diarization בשלב
התמלול ("דובר 1/2"), speaker embeddings (pyannote.audio במקור, מומש בפועל
עם sherpa-onnx/wespeaker), פרופילי קול חוצי-הקלטות ב-Firestore, מסך תיוג
דוברים, והחלפת תוויות גנריות בשם אמיתי בתמלול/בסיכום. הפיצ'ר כולו הוסר
לגמרי מהקוד (backend ו-android כאחד): התמלול הוא כעת זרם שטוח של קטעי
{טקסט, זמן התחלה, זמן סיום} בלי שום מידע על מי דיבר, הסיכום לא מייחס אמירות
לאדם ספציפי (רק כשהשם נאמר במפורש בתוכן), ומסכי "עריכת דוברים" ו"דוברים לא
מזוהים" הוסרו מהאפליקציה. הסעיפים שלמטה שמתארים את הפיצ'ר (שלב 2, סעיף 2
ב"פיצ'רים נוספים מוצעים", ההשפעה על ריבוי-משתמשים) נשארים כתיעוד היסטורי
בלבד.

## שלבי פיתוח (MVP → הרחבה)

**שלב 1 - MVP בסיסי**
- אפליקציית אנדרואיד: הקלטה + שמירה מקומית + העלאה ידנית לשרת.
- Backend: תמלול גנרי (זרם שטוח) וגם סיכום/TO DO - שניהם דרך Gemini API,
  ללא גאנט עדיין.
- יצירת תיקיית Drive לפי תאריך+נושא עם תמלול, סיכום, TO DO.

**שלב 2 - זיהוי דוברים לומד (הוסר ב-2026-08-24 - ראה "הוסר: זיהוי דוברים"
למעלה)**
- מסך תיוג דוברים באפליקציה (שם + השמעת קטע).
- שמירת embeddings ב-Firestore והתאמה אוטומטית בהקלטות עתידיות.

**שלב 3 - גאנט ואבני דרך**
- זיהוי תאריכים בטקסט המשימות (Gemini JSON structured output).
- טאב גאנט חזותי ב-Google Sheet (טווחי תאריכים + אבני דרך).
- (אופציונלי) דחיפת אבני דרך ל-Google Calendar.

**שלב 4 - ליטוש**
- עריכת סיכום ישירות מתוך האפליקציה (או הפניה ל-Google Docs).
- התראות בסיום עיבוד, טיפול בשגיאות/ניסיון חוזר, מסך היסטוריה/חיפוש.

## פיצ'רים נוספים מוצעים (לאישור המשתמש)

1. **גיליון אינדקס מרכזי** ב-Drive שמרכז את כל ההקלטות (תאריך, נושא,
   קישור לתיקייה, סטטוס משימות) - נוח לחיפוש/מעקב. גם ניתן לעריכה ידנית
   מתוך האפליקציה (לא רק דרך Drive).
2. **זיהוי אחראי ותאריך יעד אוטומטי** מתוך ניסוח חופשי ("X יעשה את Y עד
   יום שלישי") - לא רק "יש תאריך/אין תאריך" אלא שיוך משימה לאדם. ניתן
   לתיקון/שיוך ידני באפליקציה במקרה שהזיהוי האוטומטי טעה.
3. **התראות Push** בסיום עיבוד הקלטה (האפליקציה מודיעה "הסיכום מוכן").
4. **תמיכה רב-לשונית** - זיהוי שפה אוטומטי למקרה של שיחות שאינן בעברית.
5. **תיוג/קטגוריות** להקלטות (למשל "עבודה", "אישי", "פרויקט X") לסינון
   מהיר בהיסטוריה, עם אפשרות להוסיף/לערוך תגיות ידנית באפליקציה.
6. **מעקב סטטוס משימות** - סימון "בוצע"/"פתוח" ישירות בגיליון ה-TO DO
   או ידנית באפליקציה, עם אפשרות עתידית לשלוח תזכורת.

## הרחבה עתידית - ריבוי משתמשים (לא כרגע)

המשתמש ציין שבעתיד (לא בשלב הנוכחי) הוא ירצה שהאפליקציה תרוץ על כמה
טלפונים, כשכל משתמש רואה/ניגש רק להקלטות שהטלפון שלו יצר. זה משנה כמה
החלטות ארכיטקטורה שכרגע פשוטות בכוונה לצורך MVP חד-משתמשי:

- **היום**: הבקאנד כותב ל-Drive באמצעות OAuth refresh token יחיד (של
  meirww@gmail.com), ו-Firestore/UploadWorker משתמשים במזהה קבוע
  `primary_user` (ראה `android/.../UploadWorker.kt` וה-`OWNER_USER_ID`).
- **בעתיד**: כל משתמש יצטרך Google Sign-In אמיתי באפליקציה (OAuth client
  מסוג Android, לא Desktop), כדי שהשרת יכתוב להקלטות/דרייב של אותו משתמש
  ספציפית, ו-Firestore יסנן לפי מזהה המשתמש האמיתי (ולא קבוע).

אין צורך לפעול על זה עכשיו - רק לזכור בעת תכנון שלב שיתוף/ריבוי משתמשים.
